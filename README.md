# Aircraft Engine Remaining Useful Life Prediction

## Project Description

This project predicts the remaining useful life (RUL) of simulated aircraft engines using the current operating cycle, operating settings, and sensor readings. RUL represents the number of operating cycles remaining before engine failure.

The project includes exploratory data analysis, preprocessing, regression modeling, grouped cross-validation, hyperparameter tuning, and a Streamlit application.

Two target formulations are compared:

- **Full RUL:** Estimates the remaining operating cycles without an upper limit.
- **Capped RUL at 125:** Estimates remaining life up to 125 cycles. A target value of 125 represents **125 or more cycles remaining**.

## Dataset

- **Source:** NASA Prognostics Center of Excellence (PCoE), *Turbofan Engine Degradation Simulation Data Set*, item 6 in the [NASA data repository](https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/).
- **Download:** [NASA dataset ZIP](https://phm-datasets.s3.amazonaws.com/NASA/6.+Turbofan+Engine+Degradation+Simulation+Data+Set.zip).
- **Subset:** C-MAPSS FD001.
- **Training data:** 20,631 observations from 100 engines.
- **Test data:** 100 engines with trajectories ending before failure.
- **Observation:** Each row represents one engine at one operating cycle.
- **Operating conditions:** One operating condition and one fault mode involving high-pressure compressor degradation.

The data are generated through simulation rather than collected directly from aircraft in service.

### Features

| Feature | Description |
|---|---|
| `engine_id` | Engine identifier, used for grouping and tracking rather than as a model input. |
| `cycle` | Number of operating cycles completed at the time of observation. |
| `setting_1`–`setting_3` | Three operational settings describing engine operating conditions. |
| `sensor_1`–`sensor_21` | Measurements representing temperatures, pressures, rotational speeds, flow-related quantities, and other engine parameters. |

Examples of documented sensor meanings:

| Feature | Measurement | Unit |
|---|---|---|
| `sensor_2` | Total temperature at the low-pressure compressor outlet | °R |
| `sensor_3` | Total temperature at the high-pressure compressor outlet | °R |
| `sensor_4` | Total temperature at the low-pressure turbine outlet | °R |
| `sensor_7` | Total pressure at the high-pressure compressor outlet | psia |

Sensor definitions are documented in the [original NASA paper, Table 1](https://ntrs.nasa.gov/api/citations/20090029214/downloads/20090029214.pdf).

### Target Definition

For each run-to-failure training trajectory:

```python
RUL = final_recorded_cycle - current_cycle
```

For the capped formulation:

```python
RUL_capped = RUL.clip(upper=125)
```

For example, full RUL values of 180 and 220 both become 125, while values of 20 and 40 remain unchanged.

This formulation reduces the need to distinguish between engines far from failure and preserves differences within the final 125 cycles. The threshold is a modeling choice, not a physical failure boundary.

For the official test set, NASA provides the true remaining life at the last observed cycle in `RUL_FD001.txt`. Capped evaluation uses these reference values capped at the same threshold.

## Exploratory Data Analysis and Preprocessing

- Checked data types, missing values, and duplicate rows.
- Examined engine lifespans and the RUL distribution.
- Analyzed sensor trends, statistical outliers, and feature correlations.
- Retained statistical outliers because unusual readings may reflect engine degradation rather than data errors.
- Removed seven constant columns:

```text
sensor_1, setting_3, sensor_5, sensor_10,
sensor_18, sensor_19, sensor_16
```

- Excluded `engine_id` from the model inputs while retaining it for grouped validation.
- Used 18 input features after removing constant columns and the engine identifier.
- Compared full RUL with an additional target formulation capped at 125 cycles.

Target capping is separate from sensor preprocessing: it changes the prediction target rather than removing or clipping sensor outliers.

## Modeling and Validation

### Models

Four regression algorithms were explored:

- Linear Regression
- Ridge Regression (`alpha=1.0`)
- Random Forest Regressor
- Gradient Boosting Regressor

`StandardScaler` was included inside the linear model pipelines. Tree-based models used unscaled inputs.

### Grouped Cross-Validation

Five-fold `GroupKFold` was used on the training set, with `engine_id` defining the groups.

All observations from the same engine remain in a single fold. This prevents the same engine from appearing in both training and validation within a fold.

### Hyperparameter Tuning

Random Forest and Gradient Boosting were tuned using `GridSearchCV` with grouped cross-validation.

Configurations were ranked by mean validation RMSE. Scikit-learn reports negative RMSE scores during the search, which are converted to positive values for reporting.

### Official Test Evaluation

Each final model was evaluated using the last observed row of each of the 100 official FD001 test engines.

Predictions were compared with the supplied RUL reference values. For capped evaluation, the reference target was capped at 125 cycles.

## Results

### Initial Full-RUL Experiment

| Model | MAE (cycles) | RMSE (cycles) | R² |
|---|---:|---:|---:|
| Gradient Boosting | 18.831 | 25.226 | 0.632 |
| Random Forest | 19.139 | 25.606 | 0.620 |
| Ridge | 25.975 | 31.250 | 0.434 |
| Linear Regression | 25.975 | 31.250 | 0.434 |

These values describe the initial experiment. The updated comparison below reports the newer results for the two tree-based models.

### Updated Full-RUL and Capped-RUL Comparison

| Model | Target | MAE (cycles) | RMSE (cycles) | R² |
|---|---|---:|---:|---:|
| Gradient Boosting | Full RUL | 17.993 | 24.970 | 0.639 |
| Random Forest | Full RUL | 20.257 | 26.733 | 0.586 |
| Gradient Boosting | Capped at 125 | **11.943** | **16.480** | **0.831** |
| Random Forest | Capped at 125 | 12.398 | 16.735 | 0.826 |

Gradient Boosting achieved the lowest MAE and RMSE and the highest R² among the two models in both updated target formulations.

For the capped target, its average absolute error was 11.943 cycles.

### Interpreting the Comparison

The capped experiment produced lower errors and higher R² values. However, full RUL and capped RUL are different prediction targets.

Capping removes distinctions above 125 cycles and changes the target distribution. Therefore, the higher capped R² does not establish better prediction of unrestricted engine life.

- **Full RUL** is appropriate when estimating remaining cycles across the complete lifespan is the objective.
- **Capped RUL** is appropriate when the objective is estimating remaining life within a defined maintenance horizon.

A capped prediction of 125 should be interpreted as approximately **125 or more cycles remaining**, rather than exactly 125 cycles.

### Evaluation Metrics

- **MAE:** Average absolute prediction error, measured in cycles.
- **RMSE:** Prediction error in cycles, with greater weight assigned to large errors.
- **R²:** Compares squared prediction errors with those from predicting the mean true target value of the evaluation set.

Model configuration should be selected using training cross-validation. The official test set should be reserved for final performance reporting.

## Conclusions and Limitations

- Sensor readings and operating-cycle information can support RUL estimation on simulated FD001 engine trajectories.
- Gradient Boosting performed best among the two models in the updated comparison.
- Capping RUL at 125 cycles provided stronger metrics for the capped prediction task.
- FD001 covers one operating condition and one fault mode, limiting conclusions about broader engine behavior.
- Results on simulated data do not establish readiness for real-world aircraft maintenance decisions.
- Predictions do not currently include uncertainty intervals.
- Aggregate metrics do not show whether errors are concentrated near failure.
- Repeatedly using test results to guide modeling decisions can make the reported performance optimistic.

## Future Improvements

- Add rolling sensor statistics and temporal trend features.
- Evaluate errors separately for engines close to failure.
- Report uncertainty intervals and investigate overestimation of remaining life.
- Compare alternative capping thresholds using grouped training validation.
- Perform any data-driven feature selection inside cross-validation.
- Evaluate on additional C-MAPSS subsets with more operating conditions and fault modes.
- Keep target definitions and prediction labels consistent between saved models and the Streamlit application.
